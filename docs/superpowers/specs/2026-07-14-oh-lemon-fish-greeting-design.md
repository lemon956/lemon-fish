# oh-lemon-fish 启动欢迎画面设计

## 目标

为本仓库的 Fish 配置增加一个启动欢迎画面。每次打开交互式 Fish 时，在首个提示符之前依次显示：

1. 与 Oh My Zsh 安装完成画面同类的彩虹 Slant 字符标题 `oh-lemon-fish`；
2. 根据用户提供的柠檬照片自动转换得到的 64 × 32 ANSI 真彩 ASCII 字符画。

最终产物必须是 Fish 直接打印的字符和 ANSI 颜色序列，而不是 PNG、Sixel、Kitty 或 iTerm 图片协议。欢迎画面不得影响非交互式 Fish、脚本输出或后续提示符颜色，也不得在启动时依赖图片处理工具或其他外部命令。

## 已批准的视觉

### 标题

标题固定为以下五行 Slant 字形：

```text
         __          __                                 _____      __
  ____  / /_        / /__  ____ ___  ____  ____        / __(_)____/ /_
 / __ \/ __ \______/ / _ \/ __ `__ \/ __ \/ __ \______/ /_/ / ___/ __ \
/ /_/ / / / /_____/ /  __/ / / / / / /_/ / / / /_____/ __/ (__  ) / / /
\____/_/ /_/     /_/\___/_/ /_/ /_/\____/_/ /_/     /_/ /_/____/_/ /_/
```

颜色从左到右连续经过红、橙、黄、绿、蓝、紫和洋红。字形与颜色分段均静态保存，不在 Fish 启动时调用 FIGlet。

### 柠檬字符画

批准的参考图具有以下固定标识：

- 原图尺寸：225 × 225 像素；
- 原图 SHA-256：`ee584e2c89eddbb59c391860f6a7d7d7369a8073339b29ca1142e2cfdbf82119`；
- 构图：左后方完整柠檬、右前方切面，以及两片叶子；
- 目标字符画尺寸：64 列 × 32 行；
- 允许的可见字符集合：空格和 `.-=+#@`；
- 颜色：原图逐单元采样得到的 24 位 ANSI 前景色；
- 目标终端：至少 80 列、深色背景、支持真彩色的终端。

批准预览的固定标识：

- ANSI 字符流 SHA-256：`010c8a8d9336d61e18248f516558fb9cd924c648c84a2c1343b85ba7fa908251`；
- 剥离 ANSI 后的纯文本 SHA-256：`4eaa45ecff6e3bb6a1f281498f4b830cf48b069b758795e0aef79b4ff3c04995`。

这些哈希标识的是用户批准的 64 × 32 纯自动转换预览。临时预览文件位于 `/tmp`，不属于最终仓库内容。

## 自动转换规则

字符画在开发阶段一次性生成，运行时不再转换。生成规则固定如下：

1. 使用原始 225 × 225 参考图，不手工重画、分区、描边或补充切片纹理；
2. 使用 `ascii-image-converter` v1.13.1，将整张图片直接重采样为 64 × 32 个字符单元；
3. 字符密度表使用 `@#+=-..`。转换器按从暗到亮的顺序选择字符，因此深绿色叶片和暗边使用 `@`、`#`、`+`，中间调使用 `=`、`-`，明亮果肉使用 `.`；
4. 两个连续的 `.` 档位用于保留浅色果肉，避免其在深色终端上直接消失；
5. 每个单元的前景色直接使用缩放后像素的原始 RGB 值，并编码为 `38;2;R;G;B` ANSI 真彩序列；
6. 转换后若某单元的 R、G、B 三个通道都不低于 248，则确定性地替换为无颜色的空格，以移除照片的近白背景；
7. 除近白背景过滤外，不进行边缘增强、语义分割、手工遮罩或字符级修饰；
8. 最终可见输出严格保持 32 行、每行 64 列，并且只包含空格和 `.-=+#@`。

转换器及参考 PNG 只参与开发阶段生成。最终运行时数据静态嵌入 Fish 函数。

## 运行时结构

只新增 `functions/fish_greeting.fish`，定义 Fish 原生的 `fish_greeting` 函数。Fish 会在交互式 shell 启动、首个提示符出现前调用它，因此不修改 `config.fish`、`conf.d/` 或现有提示符。

函数按以下顺序工作：

1. 确认标准输出是 TTY，并排除 `TERM=dumb`；不满足条件时直接返回；
2. 打印预计算的彩虹 Slant 标题；
3. 打印一个空行；
4. 打印预计算的 64 × 32 柠檬 ANSI 字符流；
5. 显式重置颜色并换行，避免污染 Starship 或仓库自定义提示符。

真彩终端使用批准预览中的 24 位 RGB 颜色。若终端只支持 256 色，则使用由相同 RGB 单元预计算得到的 xterm-256 近似版本；字符布局不得改变。函数使用 Fish 内建 `printf` 输出，不启动 `cat`、Python、ImageMagick、Chafa、FIGlet 或 `ascii-image-converter` 等外部进程。

参考 PNG、HTML 预览和终端截图都不进入运行时路径。PNG 截图只能用于在不支持 ANSI 颜色的聊天界面中展示预览，不能作为欢迎画面的数据源或输出格式。

## 错误与兼容处理

- 非 TTY 或 `TERM=dumb` 时安静返回，不输出字符或 ANSI 控制序列；
- 颜色能力不足时只降低色深，不改变 64 × 32 字符矩阵；
- 每条输出路径都以显式 ANSI 重置结束；
- 终端宽度以至少 80 列为目标，不在运行时拉伸、裁剪或重新采样；
- 不修改 `fish_greeting` 之外的函数、通用颜色变量或提示符实现；
- 不增加运行时依赖、插件、图片文件或新的配置目录。

## 验证

实现完成后执行以下验证：

1. `fish -n functions/fish_greeting.fish` 通过语法检查；
2. 在真彩伪终端中启动交互式 Fish，确认标题、空行和柠檬依次出现；
3. 从输出中剥离 ANSI 序列，确认柠檬部分正好 32 行、每行 64 列；
4. 确认柠檬可见字符只属于空格和 `.-=+#@`；
5. 确认静态真彩字符矩阵与批准预览一致，并核对批准预览的 ANSI 与纯文本 SHA-256；
6. 人工核对彩色终端输出，确认完整柠檬、右前方切面和叶子可辨认；
7. 模拟 256 色终端，确认字符布局不变且黄色果实、浅色切面和绿色叶片仍可区分；
8. 非交互式 Fish、非 TTY 调用和 `TERM=dumb` 不产生欢迎画面；
9. 欢迎画面结束后提示符颜色正常；
10. 检查函数不引用 PNG、HTML 或外部转换器，并且启动时不创建外部进程；
11. 在同一 Fish 进程内重复调用 20 次，确认函数中位耗时不超过 50 毫秒。

## 未采用的方案

- 48 × 24 纯自动转换：尺寸较小，完整果实与切面难以区分，已被用户否决；
- 48 × 24 语义分割或手工描边：能强化轮廓，但用户选择保持纯自动转换；
- Chafa 默认 Unicode 图形字符：小尺寸细节更丰富，但不符合已选定的纯 ASCII 字符集合；
- `▀`、`▄` 半块像素采样：更接近低分辨率位图，不是本次批准的 ASCII 密度字符风格；
- 启动时动态转换 PNG：会引入图片文件、外部依赖和启动开销；
- 终端专用图片协议：Kitty、Sixel 或 iTerm 图片协议不是可复制的字符输出。
