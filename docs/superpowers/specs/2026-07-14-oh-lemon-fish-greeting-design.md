# oh-lemon-fish 启动欢迎画面设计

## 目标

为本仓库的 Fish 配置增加一个启动欢迎画面。每次打开交互式 Fish 时，在首个提示符之前依次显示：

1. 与 Oh My Zsh 安装完成画面同类的彩虹真彩、轻度右倾 Doom 字符标题 `oh-lemon-fish`；
2. 根据用户提供的柠檬照片自动增强并转换得到的 64 × 24 ANSI 真彩 ASCII 字符画。

最终产物必须是 Fish 直接打印的字符和 ANSI 颜色序列，而不是 PNG、Sixel、Kitty 或 iTerm 图片协议。欢迎画面不得影响非交互式 Fish、脚本输出或后续提示符颜色，也不得在启动时依赖图片处理工具或其他外部命令。

## 已批准的视觉

### 标题

标题固定为以下六行 Doom 字形。以 PyFiglet 1.0.4 的 `doom` 输出为基础，从上到下分别增加 5、4、3、2、1、0 个前导空格，形成轻度右倾：

```text
            _           _                                   __ _     _
          | |         | |                                 / _(_)   | |
     ___ | |__ ______| | ___ _ __ ___   ___  _ __ ______| |_ _ ___| |__
   / _ \| '_ \______| |/ _ \ '_ ` _ \ / _ \| '_ \______|  _| / __| '_ \
 | (_) | | | |     | |  __/ | | | | | (_) | | | |     | | | \__ \ | | |
 \___/|_| |_|     |_|\___|_| |_| |_|\___/|_| |_|     |_| |_|___/_| |_|
```

标题正好 6 行，最大宽度为 71 列。颜色按可见字符所在的全局列，从最左侧到最右侧在以下八个 RGB 色标之间线性插值：

1. 红 `(255, 0, 0)`；
2. 橙 `(255, 96, 0)`；
3. 黄 `(255, 224, 0)`；
4. 绿 `(0, 220, 64)`；
5. 青 `(0, 200, 255)`；
6. 蓝 `(64, 96, 255)`；
7. 紫 `(160, 64, 255)`；
8. 洋红 `(255, 0, 160)`。

空格不携带颜色；每个可见字符使用 `38;2;R;G;B` ANSI 真彩前景色，并在字符后立即重置。批准标题的固定标识为：

- Doom 基础纯文本 SHA-256：`1aa34578c083f7eb0e6305f63cd4c6dec768b043b648fde32d2bd9de29625493`；
- 右倾纯文本 SHA-256：`758a85557c85abb981dffa7763223ed926e5d2faf6f8200d47112c28e15c2acd`；
- 右倾真彩 ANSI SHA-256：`ce4807ba3b2f2c0445cce339b5683df975b1eca12154ac230e94e30c774437b2`。

字形、倾斜和颜色序列均在开发阶段静态生成；Fish 启动时不调用 PyFiglet 或其他标题生成器。

### 柠檬字符画

批准的参考图具有以下固定标识：

- 原图尺寸：225 × 225 像素；
- 原图 SHA-256：`ee584e2c89eddbb59c391860f6a7d7d7369a8073339b29ca1142e2cfdbf82119`；
- 构图：左后方完整柠檬、右前方切面，以及两片叶子；
- 目标字符画尺寸：64 列 × 24 行；
- 允许的可见字符集合：空格和 `.-=+#@`；
- 颜色：均衡增强图逐单元采样得到的 24 位 ANSI 前景色；
- 目标终端：至少 80 列、深色背景、支持真彩色的终端。

批准预览的固定标识：

- 均衡增强图 SHA-256：`3654ca78a1e1043675c9387770759bf153b9e7227793a0aed8d7469ed911eeb9`；
- ANSI 字符流 SHA-256：`a768dcc6b1a9ff91d053ff48c4e8eb1c97ed287bde924803512b7f1f7cf31247`；
- 剥离 ANSI 后的纯文本 SHA-256：`fc917acdb5302983b470eb4d8cd3e83e68e2c6f3da246b2ad3e89bc14d2c0ae2`。

这些哈希标识的是用户批准的 64 × 24 均衡细化预览。临时预览文件位于 `/tmp`，不属于最终仓库内容。

## 自动转换规则

字符画在开发阶段一次性生成，运行时不再转换。生成规则固定如下：

1. 使用原始 225 × 225 参考图，不手工重画、分区、描边或补充切片纹理；
2. 使用 ImageMagick 7.1.2-13，依次执行 `-colorspace sRGB`、`-sigmoidal-contrast 2.5x50%`、`-modulate 100,108,100` 和 `-unsharp 0x0.8+0.8+0.02`。该全图流水线轻度增强局部对比、饱和度与锐度，同时保持 225 × 225 sRGB 尺寸和纯白四角；
3. 使用 `ascii-image-converter` v1.13.1，将均衡增强图直接重采样为 64 × 24 个字符单元；
4. 字符密度表使用 `@#+=-..`。转换器按从暗到亮的顺序选择字符，因此深绿色叶片和暗边使用 `@`、`#`、`+`，中间调使用 `=`、`-`，明亮果肉使用 `.`；
5. 两个连续的 `.` 档位用于保留浅色果肉，避免其在深色终端上直接消失；
6. 每个单元的前景色直接使用均衡增强图缩放后像素的 RGB 值，并编码为 `38;2;R;G;B` ANSI 真彩序列；
7. 转换后若某单元的 R、G、B 三个通道都不低于 248，则确定性地替换为无颜色的空格，以移除照片的近白背景；
8. 除上述全图增强与近白背景过滤外，不进行语义分割、手工遮罩、描边或字符级修饰；
9. 最终可见输出严格保持 24 行、每行 64 列，并且只包含空格和 `.-=+#@`。

转换器及参考 PNG 只参与开发阶段生成。最终运行时数据静态嵌入 Fish 函数。

## 运行时结构

只新增 `functions/fish_greeting.fish`，定义 Fish 原生的 `fish_greeting` 函数。Fish 会在交互式 shell 启动、首个提示符出现前调用它，因此不修改 `config.fish`、`conf.d/` 或现有提示符。

函数按以下顺序工作：

1. 确认标准输出是 TTY，并排除 `TERM=dumb`；不满足条件时直接返回；
2. 打印预计算的 6 行 Doom 右倾彩虹标题；
3. 打印一个空行；
4. 每行先打印 4 个无颜色空格，再打印预计算的 64 × 24 柠檬 ANSI 字符流，使柠檬在标题下方居中；
5. 显式重置颜色并换行，避免污染 Starship 或仓库自定义提示符。

完整可见输出正好 31 行：6 行标题、1 行空行和 24 行柠檬；最大宽度为 71 列。批准的完整组合预览固定标识为：

- 剥离 ANSI 后的纯文本 SHA-256：`4827bd4b6fbdb09ea318d017d7c7c58ba786ef5faf48dfcd3de0943070e335c6`；
- ANSI 字符流 SHA-256：`b95e5598fffcac61a4a10bbf185fe602068e4b7ed6e8de3caf0cb9308060a28e`。

真彩终端使用批准预览中的 24 位 RGB 颜色。若终端只支持 256 色，则使用由相同 RGB 单元预计算得到的 xterm-256 近似版本；标题、空行、缩进和柠檬字符布局不得改变。函数使用 Fish 内建 `printf` 输出，不启动 `cat`、Python、ImageMagick、Chafa、FIGlet、PyFiglet 或 `ascii-image-converter` 等外部进程。

参考 PNG、HTML 预览和终端截图都不进入运行时路径。PNG 截图只能用于在不支持 ANSI 颜色的聊天界面中展示预览，不能作为欢迎画面的数据源或输出格式。

## 错误与兼容处理

- 非 TTY 或 `TERM=dumb` 时安静返回，不输出字符或 ANSI 控制序列；
- 颜色能力不足时只降低色深，不改变 6 行标题或 64 × 24 柠檬字符矩阵；
- 每条输出路径都以显式 ANSI 重置结束；
- 终端宽度以至少 80 列为目标，不在运行时拉伸、裁剪或重新采样；
- 不修改 `fish_greeting` 之外的函数、通用颜色变量或提示符实现；
- 不增加运行时依赖、插件、图片文件或新的配置目录。

## 验证

实现完成后执行以下验证：

1. `fish -n functions/fish_greeting.fish` 通过语法检查；
2. 在真彩伪终端中启动交互式 Fish，确认标题、空行和柠檬依次出现；
3. 从输出中剥离 ANSI 序列，确认标题正好 6 行、最大宽度 71 列，并与批准的右倾纯文本哈希一致；
4. 确认第 7 行为空行，柠檬部分正好 24 行；每行包含 4 个缩进空格和 64 列柠檬字符；
5. 确认柠檬 64 列负载中的可见字符只属于空格和 `.-=+#@`；
6. 确认完整输出正好 31 行、最大宽度 71 列，并核对标题、柠檬及完整组合预览的 ANSI 与纯文本 SHA-256；
7. 人工核对彩色终端输出，确认 `oh-lemon-fish` 易读，完整柠檬、右前方切面和叶子可辨认；
8. 模拟 256 色终端，确认字符布局不变，彩虹标题以及黄色果实、浅色切面和绿色叶片仍可区分；
9. 非交互式 Fish、非 TTY 调用和 `TERM=dumb` 不产生欢迎画面；
10. 欢迎画面结束后提示符颜色正常；
11. 检查函数不引用 PNG、HTML 或外部转换器，并且启动时不创建外部进程；
12. 在同一 Fish 进程内重复调用 20 次，确认函数中位耗时不超过 50 毫秒。

## 未采用的方案

- 五行 Slant 标题：风格接近参考图，但 `lemon` 和 `fish` 不易辨认，已由六行 Doom 右倾标题替代；
- Standard 与 Small 标题：Standard 更方正、Small 更紧凑，但用户选择 Doom 字形并增加轻度右倾；
- 64 × 32 纯自动转换：细节较多但整体过高，已由 64 × 24 方案替代；
- 64 × 24 未增强转换：比例合适但果肉、表皮和叶片细节偏弱，已由均衡增强流水线替代；
- 48 × 24 纯自动转换：尺寸较小，完整果实与切面难以区分，已被用户否决；
- 语义分割或手工描边：能强化轮廓，但不符合最终选择的自动照片转换风格；
- Chafa 默认 Unicode 图形字符：小尺寸细节更丰富，但不符合已选定的纯 ASCII 字符集合；
- `▀`、`▄` 半块像素采样：更接近低分辨率位图，不是本次批准的 ASCII 密度字符风格；
- 启动时动态转换 PNG：会引入图片文件、外部依赖和启动开销；
- 终端专用图片协议：Kitty、Sixel 或 iTerm 图片协议不是可复制的字符输出。
