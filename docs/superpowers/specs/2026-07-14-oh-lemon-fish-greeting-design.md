# oh-lemon-fish 启动欢迎画面设计

## 目标

为本仓库的 Fish 配置增加一个启动欢迎画面。每次打开交互式 Fish 时，在首个提示符之前依次显示：

1. 与 Oh My Zsh 安装完成画面同类的 Slant 字符标题 `oh-lemon-fish`；
2. 根据用户提供的柠檬照片直接采样生成的高保真 ANSI 真彩字符画。

欢迎画面不得影响非交互式 Fish、脚本输出或后续提示符颜色，也不得在启动时依赖图片处理工具或其他外部命令。

## 已批准的视觉

### 标题

标题固定为以下五行 Slant 字形：

```text
         __          __                                 _____      __
  ____  / /_        / /__  ____ ___  ____  ____        / __(_)____/ /_
 / __ \/ __ \______/ / _ \/ __ `__ \/ __ \/ __ \______/ /_/ / ___/ __ \
/ /_/ / / / /_____/ /  __/ / / / / / /_/ / / / /_____/ __/ (__  ) / / /
\____/_/ /_/     /_/\___/_/ /_/ /_/\____/_/ /_/     /_/ /_/____/_/ /_/
```

颜色从左到右连续经过红、橙、黄、绿、蓝、紫和洋红。字形与颜色分段均在实现中静态保存，不在 Fish 启动时调用 FIGlet。

### 柠檬字符画

批准的参考图具有以下固定标识：

- 原图尺寸：225 × 225 像素；
- SHA-256：`ee584e2c89eddbb59c391860f6a7d7d7369a8073339b29ca1142e2cfdbf82119`；
- 构图：左后方完整柠檬、右前方切面、顶部一竖一斜两片叶子；
- 颜色与叶片大小、角度、遮挡关系均来自原图，不再手绘重构。

生成过程固定如下：

1. 将与纯白色差值不超过 8 的外围背景排除，得到原图中的 `(9, 14, 212, 200)` 内容边界，即 203 × 186 像素；
2. 使用 Lanczos 重采样为 60 × 56 像素；
3. 将纵向相邻的两个像素合并为一个终端单元，最终尺寸为 60 列 × 28 行；
4. 上下像素都可见时，用 `▀` 的前景色表示上像素、背景色表示下像素；
5. 只有上像素可见时使用 `▀`，只有下像素可见时使用 `▄`，都透明时使用空格；
6. 满足“每个 RGB 通道至少为 246，且通道最大差不超过 8”的近白像素视为透明背景；
7. 其他颜色直接来自缩放后的图像像素，不套用人工黄色或绿色调色板。

该算法保留果皮高光、果肉浅黄、切面纹理和叶片明暗，同时去掉不适合深色终端的白色方形背景。

## 运行时结构

只新增 `functions/fish_greeting.fish`，定义 Fish 原生的 `fish_greeting` 函数。Fish 会在交互式 shell 启动、首个提示符出现前调用它，因此不需要修改 `config.fish`、`conf.d/` 或现有提示符。

函数按以下顺序工作：

1. 确认标准输出是 TTY；不是 TTY 时直接返回，不输出 ANSI 控制序列；
2. 打印预计算的彩虹 Slant 标题；
3. 打印一个空行；
4. 打印预计算的 60 × 28 柠檬字符画；
5. 无论采用哪种颜色路径，最后都调用 `set_color --reset` 并换行，避免污染 Starship 或仓库自定义提示符。

真彩终端使用 24 位 RGB ANSI 序列，以匹配批准的预览。若终端不支持真彩色，实现提供预计算的 256 色近似版本；`TERM=dumb` 或非 TTY 输出不显示欢迎画面。完整视觉以至少 80 列的终端为目标，不在运行时拉伸或重新采样。

所有标题和图像数据都静态存在该函数文件中。运行时不得调用 `npx`、FIGlet、Python、Pillow、ImageMagick，也不得读取参考 PNG。这样既保持图像还原度，也避免每次启动引入进程创建和图片解码成本。

## 错误与兼容处理

- 颜色能力不足时只降低色深，不改变字符布局。
- 无 TTY 时安静返回，避免污染重定向、远程复制或自动化命令输出。
- 每条输出路径都以显式颜色重置结束。
- 不修改 `fish_greeting` 之外的函数、通用颜色变量或提示符实现。
- 不增加运行时依赖、插件或新的配置目录。

## 验证

实现完成后执行以下验证：

1. `fish -n functions/fish_greeting.fish` 通过语法检查；
2. 在伪终端中启动交互式 Fish，确认标题为五行 Slant 字形，柠檬为 60 × 28 个终端单元且位于标题下方；
3. 真彩路径渲染结果与批准预览核对，确认两片叶子、完整果实、切面及主要颜色关系一致；
4. 模拟 256 色终端，确认布局不变且颜色可辨认；
5. 非交互式 Fish 和非 TTY 调用不产生欢迎画面或 ANSI 转义码；
6. 欢迎画面结束后提示符颜色正常；
7. 在同一 Fish 进程内重复调用 20 次，确认函数中位耗时不超过 50 毫秒且没有外部进程调用。

## 未采用的方案

- 手绘 ASCII 柠檬：无法准确还原叶片比例、位置和照片颜色，已被用户明确否决。
- 启动时动态转换 PNG：视觉准确，但会引入图片文件、外部依赖和明显启动成本。
- 终端专用图片协议：Kitty、Sixel 或 iTerm 图片协议并非通用字符输出，不符合“使用字符完整还原”的要求。
